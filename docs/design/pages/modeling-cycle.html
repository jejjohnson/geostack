How does a model get better, and how does it get fast without getting wrong?

Two cycles organise the modelling in the stack. The modeling cycle says how a model improves: compare its predictions with observations, and let the kind of misfit decide whether to tune the model or to change it. The six-step cycle says how a trusted but slow method becomes a fast one, with each step checked against the one before. This page runs both on one methane plume, where the first model is wrong in a way that tuning cannot fix.

TL;DR

Two loops, and a ladder of references

  • Compare decides. A misfit the noise explains is random: run the fast inner loop and estimate the state and parameters. A misfit with a pattern is systematic: run the slow outer loop and change the model or the data.
  • The inner loop cannot repair a wrong model. Here it fits model 1 as well as it can, and returns a spread coefficient of 0.58 with a confident error bar; the true value is 0.30. The misfit map still shows a pattern (χ² 2.41, where 1 means noise).
  • One structural change fixes it. Letting the wind direction be estimated gives χ² 0.95 and recovers all three parameters.
  • Then make it fast, in steps. The careful inference takes 81 s per scene; with an emulator, 3.2 s; with an amortized map, 0.51 ms.
  • Every fast step has a slower one as its referee. The emulator is scored against the simulator, emulator-based inference against the careful inference, the amortized map against emulator-based inference.
  • Fast is not free. The first amortized map was off by up to 5.8 posterior widths and said so with wide error bars; the improve step brought that to at most 1.8.

The running example

Running exampleOne methane plume, and a forecast wind that is 12° off

A facility leaks methane at a steady rate. A satellite scene shows the plume as a map of column mass, 32 × 32 pixels of 50 m, with noise. We want the emission rate \(Q\). The model is a Gaussian plume: gas blown downwind at speed \(U\), spreading sideways as it goes. The “real world” here is the same physics with one twist the first model does not know about: the wind blows 12° away from the forecast direction. Everything is synthetic, so the truth is known.

Part 1 · The modeling cycle: how a model improves

The modeling track turns an idea of how the system works into equations, then code, then predictions. The observing track turns the same system into measurements, then observations. Neither is the truth; each is a simplification, and compare is where they are confronted.

def plume(rate, spread, direction):
    """f(θ): column mass of a time-averaged Gaussian plume, in g m⁻².

    Ω(x, y) = Q / (U √(2π) σ_y(x)) · exp(−y² / 2σ_y(x)²),  σ_y(x) = a x^0.9
    with (x, y) the downwind and crosswind distance from the source.
    """
    col, row = np.meshgrid(np.arange(SIDE), np.arange(SIDE))
    east = (col[..., None, None] + SUB[:, None] - SOURCE[0]) * PIXEL_M      # (H, W, 3, 1) m
    north = (row[..., None, None] + SUB[None, :] - SOURCE[1]) * PIXEL_M     # (H, W, 1, 3) m
    angle = direction + MEANDER[:, None, None, None, None]                  # (K, 1, 1, 1, 1)
    downwind = east * np.cos(angle) + north * np.sin(angle)                 # (K, H, W, 3, 3) m
    crosswind = -east * np.sin(angle) + north * np.cos(angle)
    sigma = spread * np.maximum(downwind, 1.0) ** 0.9                       # σ_y, m
    column = rate / (WIND_M_S * np.sqrt(2 * np.pi) * sigma) * np.exp(-(crosswind**2) / (2 * sigma**2))
    column = np.where(downwind > 0, column, 0.0)
    return 1e3 * column.mean(axis=(0, 3, 4))                                # (H, W) g m⁻²

Compare: is the misfit random or systematic?

Subtract the prediction from the observation and divide by the noise level. If the model is right, what is left is noise: it averages one when squared (\(\chi^2 \approx 1\)) and a pixel tells you nothing about its neighbour. If the model is wrong, what is left has a shape.

def compare(scene, prediction):
    """Is the misfit random (the error model explains it) or systematic?"""
    residual = (scene - prediction) / NOISE
    # χ²: mean squared residual in units of the noise; 1 if the model is right
    chi2 = float(np.mean(residual**2))
    # ρ₁: correlation of each residual with its right-hand neighbour; 0 if random
    neighbour = float(np.mean(residual[:, :-1] * residual[:, 1:]) / np.mean(residual**2))
    count = residual.size
    random = chi2 < 1 + 3 * np.sqrt(2 / count) and abs(neighbour) < 3 / np.sqrt(count)
    return {"chi2": round(chi2, 3), "neighbour": round(neighbour, 3), "verdict": "random" if random else "systematic",
            "chi2_limit": round(1 + 3 * np.sqrt(2 / count), 3), "neighbour_limit": round(3 / np.sqrt(count), 3)}

The inner loop: estimate, with the model held fixed

The inner loop keeps the model's structure and adjusts its numbers: the state \(\vect{x}\) (data assimilation) or the parameters \(\gvect{\theta}\) (calibration). Here it is a sampler that proposes parameter values, runs the simulator, and keeps values in proportion to how well they explain the scene.

def log_posterior(theta, scene, forward, low, high):
    """log p(θ | y) up to a constant: flat prior in a box, Gaussian noise."""
    if np.any(theta < low) or np.any(theta > high):
        return -np.inf
    residual = scene - forward(theta)
    return -0.5 * np.sum(residual**2) / NOISE**2


def metropolis(scene, forward, start, low, high, steps, rng):
    """Random-walk Metropolis; the proposal adapts to the chain during burn-in."""
    dims = len(start)
    theta, value = np.array(start, float), log_posterior(start, scene, forward, low, high)
    step = np.diag(((high - low) * 0.02) ** 2)
    chain, calls = [], 1
    for index in range(steps):
        if index in (300, 700, 1200):
            step = 2.38**2 / dims * np.cov(np.array(chain[index // 2:]).T) + 1e-12 * np.eye(dims)
        proposal = rng.multivariate_normal(theta, step)
        proposed = log_posterior(proposal, scene, forward, low, high)
        calls += 1
        if np.log(rng.uniform()) < proposed - value:
            theta, value = proposal, proposed
        chain.append(theta.copy())
    return np.array(chain[1500:]), calls

Watch out

With model 1 the inner loop did its job: χ² fell from 3.30 to 2.41. It did so by widening the plume to cover the direction error, so the spread coefficient came out at 0.58 ± 0.01, about twice the truth, with a small error bar. An estimate is only as good as the model it is conditioned on, and its error bar does not include the model being wrong.

The outer loop: change the structure

A systematic misfit means something is missing. The misfit map says what: positive on one side of the plume, negative on the other, the mark of a plume pointing the wrong way. The refinement is one new parameter, the wind direction. The same inner loop then finds 12.0° and the misfit becomes noise. The other branch of the outer loop, dashed in the figure, changes the observing side instead: a better wind product, a second overpass, a finer sensor.

Which loop to take
  • Inner loop when the misfit passes the tests for noise, or fails them only because the numbers are not yet tuned. Cheap, automatic, repeated on every new scene.
  • Outer loop when the inner loop has converged and a pattern remains. Expensive, done by people, and it invalidates what was built on the old model.
  • Start simple. Add structure only when compare demands it; a model with more freedom than the data can constrain will pass the tests for the wrong reason.

The two tests here are the simplest that work. Real ones look at misfit by region, season, regime and lead time, and they are worth writing down as a benchmark before the model exists.

Part 2 · The six-step cycle: how a trusted method becomes a fast one

Model 2 passes compare. The inference that established it takes about a minute per scene, which is fine for one plume and hopeless for a satellite archive. The six-step cycle makes it fast without losing track of whether it is still right.

Step 1 · Simple model

The generative story: parameters go through the physics \(f\) and the instrument \(h\), and noise is added. It serves twice: as the thing step 2 inverts, and as a source of as many labelled examples as you care to simulate. Here, 4 000 pairs took 53 s.

Step 2 · Model-based inference: the oracle

The classical method, already run above as the inner loop: 6 001 simulator calls, 81 s. It is called the oracle because it is the most trusted reference available, and not because it is exact. Everything faster is judged against it.

Step 3 · Emulator

A cheap function trained to imitate the simulator. This one compresses the simulated maps to 40 numbers and learns how those numbers depend on the parameters. Its referee is step 1: on 300 simulations it never saw, how far is it from the simulator, in units of the observation noise?

class Emulator:
    """f̂(θ; θ_emu): θ → principal components of the field → field."""

    def __init__(self, components=40, seed=0):
        self.scale_in = sklearn.preprocessing.StandardScaler()
        self.basis = sklearn.decomposition.PCA(components)
        self.scale_out = sklearn.preprocessing.StandardScaler()
        self.network = sklearn.neural_network.MLPRegressor(
            hidden_layer_sizes=(128, 128), max_iter=3000, tol=1e-6, random_state=seed
        )

    def fit(self, thetas, fields):
        # the field is linear in Q, so emulate the field per unit rate
        unit = fields.reshape(len(fields), -1) / thetas[:, :1]
        codes = self.scale_out.fit_transform(self.basis.fit_transform(unit))
        self.network.fit(self.scale_in.fit_transform(thetas[:, 1:]), codes)
        return self

    def __call__(self, theta):
        code = self.network.predict(self.scale_in.transform(np.atleast_2d(theta)[:, 1:]))
        unit = self.basis.inverse_transform(self.scale_out.inverse_transform(code))
        return (theta[0] * unit).reshape(SIDE, SIDE)

Step 5 · Amortized inference

The last step removes the sampler. A network is trained on simulated scenes to output the answer directly: a mean and a spread for each parameter. All the cost is paid in training; a new scene takes one forward pass.

class Amortized:
    """q(θ | y; ν): scene → a Gaussian over θ, in one forward pass."""

    def __init__(self, hidden=(128, 128), seed=0):
        self.basis = sklearn.decomposition.PCA(60)
        self.scale = sklearn.preprocessing.StandardScaler()
        self.scale_theta = sklearn.preprocessing.StandardScaler()
        options = dict(max_iter=600, tol=1e-6, early_stopping=True, random_state=seed)
        self.mean = sklearn.neural_network.MLPRegressor(hidden_layer_sizes=hidden, **options)
        self.spread = sklearn.neural_network.MLPRegressor(hidden_layer_sizes=(64, 64), **options)

    def features(self, scenes):
        return self.basis.transform(scenes.reshape(len(scenes), -1))

    def fit(self, thetas, scenes):
        half = len(thetas) // 2
        self.basis.fit(scenes.reshape(len(scenes), -1))
        features = self.scale.fit_transform(self.features(scenes))
        targets = self.scale_theta.fit_transform(thetas)
        # ν for the mean, on the first half
        self.mean.fit(features[:half], targets[:half])
        # ν for the spread, on the second half's squared errors: log e² ≈ log σ² − 1.27
        error = targets[half:] - self.mean.predict(features[half:])
        self.spread.fit(features[half:], np.log(error**2 + 1e-9) + 1.27)
        return self

    def __call__(self, scene):
        features = self.scale.transform(self.features(scene[None]))
        mean = self.scale_theta.inverse_transform(self.mean.predict(features))[0]
        std = np.sqrt(np.exp(self.spread.predict(features)[0])) * self.scale_theta.scale_
        return mean, std

Step 5's referee is step 4, on twenty fresh scenes. The first map is blunt: its best guess sits 1.3 to 5.8 posterior widths from where the sampler puts it, depending on the parameter. It is honest about that, though: its own error bars are several times wider, and they contain the truth as often as they claim. A larger network on three times the data closes most of the gap. It is still less sharp than the sampler, at 0.51 ms a scene.

How the two cycles fit together

What the feedback buys, and what it costs
  • The classical method is never retired. It becomes the referee. Without step 2 there is nothing to say whether steps 3 to 5 are right.
  • Each fast step is trusted only as far as it was tested. The emulator was trained inside a box of parameter values; outside it, nothing is promised.
  • Error bars need their own check. A network's stated spread is a prediction like any other; count how often its intervals contain the truth.
  • A structural change resets the fast steps. The emulator and the amortized map were trained on model 2's simulations. Change the model and they are confidently describing the old one.
  • Every arrow is a benchmark. Each comparison in the table above has a fixed input, a reference and a score, so it can be rerun whenever anything changes.

The costs are real: a simulation budget up front, a training pipeline to maintain, and the discipline to rerun the referees.
