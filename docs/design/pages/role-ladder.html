GeoStack · background · noun → paragraph

Where does a piece of code belong?

Pictures first. A library is a small language: it has things, actions on things, ways of acting, and whole jobs built from them. The role ladder names seven levels of that language, from the data at the bottom to a complete recipe at the top, and says what each level may use. This page teaches the ladder with one job, a methane emission rate from a satellite scene, written first as a notebook cell and then rung by rung.

TL;DR

Seven rungs, one direction

  • The ladder is grammar. ⓪ structures are nouns, ① primitives verbs, ② strategies adverbs, ③ models noun phrases, ④ algorithms sentences, ⑤ steps sentences with their own settings, ⑥ recipes paragraphs.
  • Calls go down only. A rung is written with the rungs below it and knows nothing of those above, so the ladder is also the order to build and test in.
  • The lower five compute on plain arrays. Geographic data and saved settings enter at ⑤, where a step unwraps the data, calls down, and wraps the result.
  • Composition stops at ⑥. A recipe of recipes is a recipe. Running one (when, where, on what) is orchestration, which is not a rung.
  • It pays three ways: reuse a piece, swap a method, save a job. Here: one fitted background serves two stages; a different estimator is a one-word change; the recipe saved as JSON and loaded back returns the same 5.68 kg s⁻¹.

The running example

Running exampleA methane plume: radiance in, emission rate out

The job from the kinds and roles design page, at a size that runs in a second. A hyperspectral scene holds a methane plume. A matched filter turns radiance into a methane enhancement, a threshold masks the plume, and the plume's mass and the wind give an emission rate. The scene is synthetic, so the true answer is known.

QuantitySymbolValueUnit
Scene\(\mathbf{{x}}\)40 × 96 × 96band × row × col

The problem: code with no address

# Shapes: B = 40 bands; R × C = 96 × 96 pixels; P = R C pixels
spectra = radiance.reshape(40, -1).T
mean = spectra.mean(axis=0)
covariance = sklearn.covariance.LedoitWolf().fit(spectra).covariance_
target = -air_mass * absorption * mean
direction = np.linalg.solve(covariance, target)
enhancement = np.tensordot(direction, radiance - mean[:, None, None], axes=1)
enhancement /= target @ direction
noise = (target @ direction) ** -0.5
labels, count = scipy.ndimage.label(enhancement > 3 * noise)
...
emission = 3.5 * 6.56e-7 * 3600 * enhancement[plume].sum() / length

Every line is fine. The trouble is structural: the covariance estimator, the filter, the threshold rule and the settings are fused, so none can be used, replaced or recorded alone. The ladder is the fix: give every piece a level, and a rule for what each level may touch.

The ladder

Two things on the ladder are easy to miss. Orchestration is not a rung: it does not compose anything, it runs what has been composed. And a Module is not a rung either; it is a way of packaging (an object whose setup runs once and whose call is fast afterwards), used by three rungs: ⓪, ② and ③.

Part 1 · The rungs, one at a time

⓪ Structures: the nouns

A structure is a thing: the data, or a mathematical object with a shape worth knowing (a diagonal matrix, a grid). It does nothing by itself. Here the noun is the scene: an array with its pixel size and attributes. In the stack it is a GeoArray; the small stand-in below keeps the page runnable.

# Shapes: B = 40 bands; R × C = 96 × 96 pixels; P = R C pixels


# user
@dataclasses.dataclass(frozen=True)
class Scene:
    """A small carrier: the numbers, the pixel size and the attributes."""

    data: np.ndarray
    pixel_m: float
    attrs: dict

① Primitives: the verbs

A primitive is one call on a noun, a plain function of arrays and numbers. It knows nothing of methane plumes or satellites: the area of a pixel, the connected pieces of a mask.

# user
def target_signature(
    mean: Float[np.ndarray, " band"],
    absorption: Float[np.ndarray, " band"],
    air_mass: float,
) -> Float[np.ndarray, " band"]:
    """Radiance change per ppm m of methane: t = −M (k ⊙ μ)."""
    # t = −M (k ⊙ μ)
    target = -air_mass * absorption * mean                    # (B,), (B,) → (B,)
    return target


# user
def pixel_area(pixel_m: float) -> float:
    """Area of one square pixel in m²: a = Δs²."""
    # a = Δs²
    area = pixel_m * pixel_m                                  # → ()
    return area


# user
def large_components(
    mask: Bool[np.ndarray, "y x"], min_pixels: int
) -> Bool[np.ndarray, "y x"]:
    """Keep connected pieces of at least N_min pixels: b_n = c_n 1[|K(n)| ≥ N_min]."""
    # K(n): the connected piece that holds pixel n
    labels, count = scipy.ndimage.label(mask)                 # (R, C) → (R, C)
    sizes = np.bincount(labels.ravel(), minlength=count + 1)  # (R, C) → (K + 1,)
    keep = sizes >= min_pixels                                # (K + 1,) → (K + 1,)
    # label 0 is the background, never a plume
    keep[0] = False
    # b_n = c_n 1[|K(n)| ≥ N_min]
    plume = keep[labels]                                      # (R, C) → (R, C)
    return plume

② Strategies: the adverbs

A strategy says how something is done and holds settings only, never data: which covariance estimator, which threshold rule. Two strategies that answer the same question are interchangeable, which is the point.

# user
@dataclasses.dataclass(frozen=True)
class LedoitWolf:
    """How to estimate Σ: shrink the sample covariance towards a scaled identity."""

    def __call__(
        self, spectra: Float[np.ndarray, "pixel band"]
    ) -> Float[np.ndarray, "band band"]:
        estimator = sklearn.covariance.LedoitWolf()
        fitted = estimator.fit(spectra)
        return fitted.covariance_                             # (P, B) → (B, B)


# user
@dataclasses.dataclass(frozen=True)
class SampleCovariance:
    """How to estimate Σ: the plain sample covariance."""

    def __call__(
        self, spectra: Float[np.ndarray, "pixel band"]
    ) -> Float[np.ndarray, "band band"]:
        return np.cov(spectra, rowvar=False)                  # (P, B) → (B, B)


# user
@dataclasses.dataclass(frozen=True)
class SigmaThreshold:
    """How to pick candidate pixels: above k noise levels."""

    k: float = 3.0

    def __call__(
        self, values: Float[np.ndarray, "y x"], noise: float
    ) -> Bool[np.ndarray, "y x"]:
        # c_n = 1[y_n > k σ_y]
        return values > self.k * noise                        # (R, C) → (R, C)

③ Models: the noun phrases

A model is a noun with meaning and fitted state: not “a matrix” but “this scene's background”, with its mean and covariance and the things only it can answer (solve with Σ, the noise of a filter built on it).

# user
@dataclasses.dataclass(frozen=True)
class Background:
    """What was fitted: the scene's mean spectrum μ and covariance Σ."""

    mean: np.ndarray
    covariance: np.ndarray

    @classmethod
    def fit(
        cls,
        spectra: Float[np.ndarray, "pixel band"],
        estimator: LedoitWolf | SampleCovariance = LedoitWolf(),
    ) -> Background:
        # μ_b = (1 / P) ∑_n x_nb
        mean = einx.mean("[pixel] band", spectra)             # (P, B) → (B,)
        # Σ, by the chosen strategy
        covariance = estimator(spectra)                       # (P, B) → (B, B)
        return cls(mean, covariance)

    def solve(self, vector: Float[np.ndarray, " band"]) -> Float[np.ndarray, " band"]:
        # s = Σ⁻¹ t
        return np.linalg.solve(self.covariance, vector)       # (B,) → (B,)

    def noise(self, target: Float[np.ndarray, " band"]) -> float:
        # σ_y = (tᵀ Σ⁻¹ t)^(−1/2)
        direction = self.solve(target)                        # (B,) → (B,)
        precision = einx.dot("band, band ->", target, direction)  # → ()
        return float(precision) ** -0.5

④ Algorithms: the sentences

An algorithm is a method over models, written as a function: do this, to that, in this way. It takes the model as an argument, so it never refits anything.

# user
def matched_filter(
    radiance: Float[np.ndarray, "band y x"],
    background: Background,
    target: Float[np.ndarray, " band"],
) -> Float[np.ndarray, "y x"]:
    """Methane enhancement per pixel: y_n = sᵀ (x_n − μ) / (tᵀ s), s = Σ⁻¹ t."""
    # s = Σ⁻¹ t
    direction = background.solve(target)                      # (B,) → (B,)
    # tᵀ s
    normalisation = einx.dot("band, band ->", target, direction)  # → ()
    # r_n = x_n − μ
    residual = einx.subtract(                                 # (B, R, C) → (B, R, C)
        "band y x, band -> band y x", radiance, background.mean
    )
    # sᵀ r_n
    projection = einx.dot("band, band y x -> y x", direction, residual)  # → (R, C)
    # y_n = sᵀ r_n / (tᵀ s)
    enhancement = projection / normalisation                  # (R, C) → (R, C)
    return enhancement


# user
def segment(
    values: Float[np.ndarray, "y x"],
    noise: float,
    rule: SigmaThreshold,
    min_pixels: int,
) -> Bool[np.ndarray, "y x"]:
    """Plume mask: candidates by the rule, then only the large pieces."""
    # c_n = 1[y_n > k σ_y]
    candidates = rule(values, noise)                          # (R, C) → (R, C)
    # b_n = c_n 1[|K(n)| ≥ N_min]
    plume = large_components(candidates, min_pixels)          # (R, C) → (R, C)
    return plume


# user
def emission_rate(
    values: Float[np.ndarray, "y x"],
    plume: Bool[np.ndarray, "y x"],
    area: float,
    wind: float,
    kappa: float,
) -> float:
    """Emission rate from the plume's mass and the wind: Q = U κ a ∑ b y / L."""
    # L = (a ∑_n b_n)^(1/2)
    length = (area * np.count_nonzero(plume)) ** 0.5          # → ()
    # ∑_n b_n y_n
    total = float(np.sum(values, where=plume))                # (R, C) → ()
    # Q = U κ a ∑_n b_n y_n / L
    rate = wind * kappa * area * total / length               # → ()
    return rate
The test for rungs ⓪ to ④

They all work on plain arrays, so they can be tested with a few random numbers, traced by JAX, and reused by any container.

  • ② or ③? If it holds only settings it is a strategy; once it holds something fitted to data it is a model.
  • ① or ④? A primitive acts on a noun; an algorithm takes a model. pixel_area is ①, matched_filter is ④.
  • None of them reads a file, a config or a coordinate reference system.

When one object both fits and applies (a matched filter class that refits its background on every call), split it: the state becomes a model, the call becomes an algorithm. That split is what let segmentation reuse σ.

⑤ Steps: a sentence with its own settings

A step does one transformation of real data and is ready to chain. It has three parts: unwrap the carrier into arrays, call down the ladder, wrap the result as a carrier again. Its constructor arguments are its settings, and they are plain values, so they can be written to JSON.

ESTIMATORS = {"ledoit_wolf": LedoitWolf, "sample": SampleCovariance}


# user
class MethaneRetrieval(pipekit_ops.Operator):
    """Step: radiance scene → enhancement scene, with its noise in the attrs."""

    def __init__(self, *, estimator: str = "ledoit_wolf") -> None:
        self.estimator = estimator

    def _apply(self, scene: Scene) -> Scene:
        # --- unwrap: arrays and numbers out of the carrier ---
        spectra = einx.id("band y x -> (y x) band", scene.data)   # (B, R, C) → (P, B)
        absorption = scene.attrs["absorption"]
        air_mass = scene.attrs["air_mass"]
        # --- compute: ② strategy, ③ model, ① primitive, ④ algorithm ---
        strategy = ESTIMATORS[self.estimator]()
        background = Background.fit(spectra, strategy)
        target = target_signature(background.mean, absorption, air_mass)
        values = matched_filter(scene.data, background, target)   # → (R, C)
        # --- rewrap: a carrier again, σ_y carried for the next step ---
        attrs = {"noise_ppm_m": background.noise(target)}
        return Scene(values, scene.pixel_m, attrs)


# user
class PlumeSegmentation(pipekit_ops.Operator):
    """Step: enhancement scene → plume mask."""

    def __init__(self, *, k: float = 3.0, min_pixels: int = 20) -> None:
        self.k = k
        self.min_pixels = min_pixels

    def _apply(self, enhancement: Scene) -> Scene:
        noise = enhancement.attrs["noise_ppm_m"]
        rule = SigmaThreshold(self.k)
        plume = segment(enhancement.data, noise, rule, self.min_pixels)
        return Scene(plume, enhancement.pixel_m, {})


# user
class EmissionRate(pipekit_ops.Operator):
    """Step: enhancement and mask → emission rate in kg s⁻¹."""

    def __init__(self, *, wind_m_s: float = 3.5, kappa: float = 6.56e-7) -> None:
        self.wind_m_s = wind_m_s
        self.kappa = kappa

    def _apply(self, enhancement: Scene, plume: Scene) -> float:
        area = pixel_area(enhancement.pixel_m)
        return emission_rate(
            enhancement.data, plume.data, area, self.wind_m_s, self.kappa
        )

⑥ Recipes: the paragraphs

A recipe puts steps in order to make one job, from source to product. It contains no computation of its own. Because it holds only steps and their settings, it exists in two forms: code, and data.

# user
def plume_recipe(
    *, k: float = 3.0, estimator: str = "ledoit_wolf"
) -> pipekit_ops.Graph:
    """Recipe: retrieval, segmentation and quantification, wired into one job."""
    # today (pipekit)
    scene_in = pipekit_ops.Input("scene")
    enhancement = MethaneRetrieval(estimator=estimator)(scene_in)
    plume = PlumeSegmentation(k=k)(enhancement)
    emission = EmissionRate()(enhancement, plume)
    # today (pipekit)
    return pipekit_ops.Graph(
        inputs={"scene": scene_in}, outputs={"emission": emission}
    )
The test between ⑤ and ⑥
  • Step: does one thing to its input. It may be complicated inside; Reproject resamples and warps and is still one closed block with settings.
  • Recipe: puts steps (its own, or ones you hand it) in order. The combinators that join steps (Sequential, Graph, Branch) live here too.

Names can mislead: geoops' RGBRecipe is a step, not a recipe. Ask how it is built.

Part 3 · The rules that make it a ladder

RuleWhat it meansWhy
Calls go downa rung uses the rungs below it, never those aboveanything can be tested without what is built on it; the ladder is the build order
Arrays below ⑤rungs ⓪ to ④ take arrays and numbers, never a georeferenced containerthe maths runs on any container, under jit, in any library
Settings stop at ⑤configs build steps and recipes; lower rungs take plain valuesone place where settings are named and saved
Composition is closeda recipe of recipes is a recipe, so the ladder ends at ⑥what lies above is running, not composing
One name, one runga public name has exactly one rolethe docs, the tests and the reader all know where to look

The role also fixes the packaging: ① and ④ are functions, ⓪, ② and ③ are Modules, ⑤ and ⑥ are Operators. One entanglement is allowed and documented: a verb may take an adverb (solve(A, b, solver=CGSolver())), and some adverbs call verbs.

Who works where

This is why the top two rungs get the strictest stability promises and the friendliest errors: they are the surface most people touch. And since floors leak, every step's documentation names the algorithm it wraps, so a user can go one rung down without reading source.
