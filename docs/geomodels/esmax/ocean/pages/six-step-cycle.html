The six-step cycle, written in probabilities

The six-step figure is usually read with functions: a model \(f\), an operator \(H\), an emulator \(f(\cdot;\phi)\). This page rewrites every box as a statement about distributions: a prior, a likelihood, a posterior, and learned densities that approximate them. A deterministic model then becomes one special case instead of the starting point. Nothing here assumes linearity; linear and nonlinear instances appear only as worked examples underneath each step, to show where closed forms come from and why they stop.

TL;DR

Six boxes, six distributions

  • Step 1 is a joint distribution \(p(\theta)\,p(z\mid\theta)\,p(y\mid z)\) you can sample. A deterministic simulator is the special case where \(p(z\mid\theta)\) is a point mass.
  • Step 2 is the posterior \(p(\theta, z\mid y)\) of that joint. It is exact by definition; every algorithm (Kalman, 4D-Var, EnKF, particles, MCMC) is an approximation of it, slow but trusted.
  • Steps 3 to 5 replace densities with learned ones: \(q_\phi\) for the simulator's transition (emulator), the same posterior computed with \(q_\phi\) (step 4), and \(q_\psi\) for the posterior itself (amortized). Each is trained by a KL divergence to the distribution it replaces.
  • Training and use are separate phases. Steps 3 and 5 are fitted once, offline, on simulations. Then every route (2, 4 or 5) returns posterior draws, and the draws are used: estimates, forecasts, predictions of new data, probabilities of events.
  • Step 6 compares distributions: each learned one against the one it approximates, and the whole model against data.
  • Linear-Gaussian is the one case where every integral is matrix algebra. Outside it, posteriors skew and split, their shape depends on the data, and every shortcut that assumes one Gaussian can fail.

Why distributions instead of functions

Every deterministic habit is a probabilistic statement with something set to zero. Writing the probability keeps the thing that was set to zero visible:

Deterministic habitThe distribution it isWhat it silently assumes
\(z_k = f_\theta(z_{k-1})\)\(p(z_k\mid z_{k-1},\theta) = \delta\big(z_k - f_\theta(z_{k-1})\big)\)the model is perfect
\(y = h(z) + \varepsilon\)\(p(y\mid z) = p_\varepsilon\big(y - h(z)\big)\)additive noise of one known shape
minimise a squared errormaximise a Gaussian log-likelihood with fixed varianceGaussian errors of known, constant size

The practical reason is that model error, emulator error and estimation error all have to live somewhere. In the probabilistic form each has a place: in \(p(z_k\mid z_{k-1},\theta)\), in \(q_\phi\), and in \(p(z\mid y)\). In the functional form they have none, and they reappear as overconfident analyses.

\[ p(z) = \mathcal N(z;\ 0.5,\ 1^2), \qquad p(y\mid z) = \mathcal N(y;\ z^2,\ 0.25^2). \]

Step 1 · The simple model is a joint distribution

A state-space model is four conditional densities. Their product is the joint distribution of everything, observed or not:

\[ p(\theta, z_{0:K}, y_{1:K}) \;=\; p(\theta)\;p(z_0\mid\theta)\;\prod_{k=1}^{K} p(z_k\mid z_{k-1},\theta, x, u_k)\;\prod_{k=1}^{K} p(y_k\mid z_k, m_k). \] 
  α ─────────► θ
               │
               ▼
  z₀ ──► z₁ ──► z₂ ──► … ──► z_K        transition  p(zₖ | zₖ₋₁, θ, x, uₖ)
         │      │             │
         ▼      ▼             ▼
         y₁     y₂            y_K        likelihood  p(yₖ | zₖ, mₖ)

"Physics you can simulate" means you can draw from this joint by ancestral sampling: draw each variable given its parents, in order. That is all step 1 has to provide, and it is all steps 3 and 5 need for training. The prior predictive \(p(y) = \iint p(\theta)\,p(z\mid\theta)\,p(y\mid z)\,\mathrm dz\,\mathrm d\theta\) is what the model expects to observe before seeing any data; drawing from it and comparing with real maps is the first check of a model.

import einx
import equinox as eqx
import jax
from jaxtyping import Array, Float, PRNGKeyArray

# Shapes: T days (time); N state values (state); M observations per day (obs);
#         P parameters (param); D any density's event shape

# not pinned (distribution library: numpyro / distrax / tfp-style)
# Dist: an object with .sample(key) and .log_prob(value)


class StateSpaceModel(eqx.Module):
    """p(θ) p(z₀ | θ) ∏ₖ p(zₖ | zₖ₋₁, θ, x, uₖ) p(yₖ | zₖ, mₖ): four conditionals."""

    # p(θ)
    def prior_params(self) -> Dist: ...

    # p(z₀ | θ)
    def prior_state(self, params) -> Dist: ...

    # p(zₖ | zₖ₋₁, θ, x, uₖ): physics, a hybrid, or an emulator
    def transition(self, state, params, covariates, control) -> Dist: ...

    # p(yₖ | zₖ, mₖ)
    def likelihood(self, state, mask) -> Dist: ...


def sample_joint(
    model: StateSpaceModel,
    covariates: Float[Array, "variable state"],
    controls: Float[Array, "time state"],
    masks: Float[Array, "time obs state"],
    *,
    key: PRNGKeyArray,
) -> tuple[Float[Array, "param"], Float[Array, "time state"], Float[Array, "time obs"]]:
    params_key, state_key, time_key = jax.random.split(key, 3)
    # θ ~ p(θ)
    params = model.prior_params().sample(params_key)  # → (P,)
    # z₀ ~ p(z₀ | θ)
    state = model.prior_state(params).sample(state_key)  # → (N,)

    def day(state, inputs):
        control, mask, day_key = inputs
        transition_key, obs_key = jax.random.split(day_key)
        # zₖ ~ p(zₖ | zₖ₋₁, θ, x, uₖ)
        state = model.transition(state, params, covariates, control).sample(
            transition_key
        )                                             # (N,) → (N,)
        # yₖ ~ p(yₖ | zₖ, mₖ)
        obs = model.likelihood(state, mask).sample(obs_key)  # (N,) → (M,)
        return state, (state, obs)

    day_keys = jax.random.split(time_key, controls.shape[0])  # → (T, 2)
    # ancestral sampling: one draw of (θ, z₁:T, y₁:T) from the joint
    _, (states, observations) = jax.lax.scan(         # → (T, N), (T, M)
        day, state, (controls, masks, day_keys)
    )
    return params, states, observations

Nothing is trained in step 1. Its hyperparameters α can be calibrated against data, which is step 6's job.
Linear-Gaussian instance \[ p(z_k\mid z_{k-1}) = \mathcal N(\mathbf M z_{k-1},\ \mathbf Q), \quad p(y_k\mid z_k) = \mathcal N(\mathbf H z_k,\ \mathbf R). \] Every marginal and conditional of the joint is Gaussian, so the whole joint is one (very large) Gaussian.
Nonlinear instance \[ p(z_k\mid z_{k-1}) = \mathcal N(f_\theta(z_{k-1}),\ \mathbf Q), \quad p(y_k\mid z_k) = \mathcal N(h(z_k),\ \mathbf R). \] Each conditional is still Gaussian, but the joint is not: pushing a Gaussian through \(f_\theta\) or \(h\) bends it. The QG model of the other pages is this case.

Step 2 · Model-based inference is the posterior of that joint

Condition the joint on what was observed. Bayes' rule gives the target and its normaliser, the evidence:

\[ p(\theta, z\mid y) = \frac{p(\theta)\,p(z\mid\theta)\,p(y\mid z)}{p(y)}, \qquad p(y) = \iint p(\theta)\,p(z\mid\theta)\,p(y\mid z)\,\mathrm dz\,\mathrm d\theta . \]

Two marginals are usually what is wanted: the state, \(p(z\mid y) = \int p(\theta, z\mid y)\,\mathrm d\theta\), and the parameters, \(p(\theta\mid y)\propto p(\theta)\,p(y\mid\theta)\), whose likelihood \(p(y\mid\theta) = \int p(z\mid\theta)\,p(y\mid z)\,\mathrm dz\) integrates the state out. For a state-space model the integrals over \(z\) split day by day into two recursions that hold for any densities:

\[ \begin{aligned} \text{predict:}\quad & p(z_k\mid y_{1:k-1}) = \int p(z_k\mid z_{k-1},\theta)\;p(z_{k-1}\mid y_{1:k-1})\;\mathrm dz_{k-1},\\ \text{update:}\quad & p(z_k\mid y_{1:k}) = \frac{p(y_k\mid z_k)\;p(z_k\mid y_{1:k-1})}{p(y_k\mid y_{1:k-1})}, \qquad p(y_k\mid y_{1:k-1}) = \int p(y_k\mid z_k)\,p(z_k\mid y_{1:k-1})\,\mathrm dz_k,\\ \text{evidence:}\quad & p(y_{1:K}\mid\theta) = \prod_{k=1}^{K} p(y_k\mid y_{1:k-1},\theta),\\ \text{smooth:}\quad & p(z_k\mid y_{1:K}) = p(z_k\mid y_{1:k})\int\frac{p(z_{k+1}\mid z_k,\theta)\;p(z_{k+1}\mid y_{1:K})}{p(z_{k+1}\mid y_{1:k})}\,\mathrm dz_{k+1}. \end{aligned} \]

Filtering is predict-then-update, forward in time; smoothing (reanalysis) runs backward once the window is filtered. Every algorithm in data assimilation is a way of evaluating these integrals, or the posterior they define, approximately. All of them start from the log joint:

# Shapes: T days (time); N state values (state); M observations per day (obs)


def log_joint(
    model, params, initial, states, observations, covariates, controls, masks
):
    # log p(θ)
    log_prior_params = model.prior_params().log_prob(params)  # → ()
    # log p(z₀ | θ)
    log_prior_state = model.prior_state(params).log_prob(initial)  # → ()
    previous = einx.rearrange(                        # (N,), (T, N) → (T, N)
        "state, time state -> (1 + time) state", initial, states
    )[:-1]

    def day_terms(prev, state, control, mask, obs):
        # log p(zₖ | zₖ₋₁, θ, x, uₖ)
        log_trans = model.transition(prev, params, covariates, control).log_prob(state)
        # log p(yₖ | zₖ, mₖ)
        log_lik = model.likelihood(state, mask).log_prob(obs)
        return log_trans, log_lik

    log_trans, log_lik = jax.vmap(day_terms)(         # → (T,), (T,)
        previous, states, controls, masks, observations
    )
    # log p(θ, z₀:T, y₁:T)
    #   = log p(θ) + log p(z₀|θ) + ∑ₖ log p(zₖ|zₖ₋₁, θ) + ∑ₖ log p(yₖ|zₖ)
    total = log_prior_params + log_prior_state        # → ()
    total = total + einx.sum("time ->", log_trans)    # → ()
    total = total + einx.sum("time ->", log_lik)      # → ()
    return total

The most general way to evaluate the recursions is to represent each density by samples: the bootstrap particle filter. It assumes nothing about linearity or Gaussianity, and it also returns an estimate of \(\log p(y\mid\theta)\):

# Shapes: T days (time); N state values (state); M obs per day (obs);
#         P_n = 1,000 particles (particle)


def particle_filter(model, params, observations, covariates, controls, masks, *, key):
    """Bootstrap filter: p(zₖ | y₁:ₖ) as weighted samples, and log p(y₁:T | θ)."""
    init_key, time_key = jax.random.split(key)
    init_keys = jax.random.split(init_key, NUM_PARTICLES)  # → (P_n, 2)
    # z₀⁽ⁱ⁾ ~ p(z₀ | θ)
    particles = jax.vmap(                             # → (P_n, N)
        lambda k: model.prior_state(params).sample(k)
    )(init_keys)

    def day(particles, inputs):
        obs, control, mask, day_key = inputs
        move_key, resample_key = jax.random.split(day_key)
        move_keys = jax.random.split(move_key, NUM_PARTICLES)  # → (P_n, 2)
        # predict: zₖ⁽ⁱ⁾ ~ p(zₖ | zₖ₋₁⁽ⁱ⁾, θ)  (Monte Carlo Chapman–Kolmogorov)
        particles = jax.vmap(                         # (P_n, N) → (P_n, N)
            lambda z, k: model.transition(z, params, covariates, control).sample(k)
        )(particles, move_keys)
        # update: log wₖ⁽ⁱ⁾ = log p(yₖ | zₖ⁽ⁱ⁾)
        log_weights = jax.vmap(                       # (P_n, N) → (P_n,)
            lambda z: model.likelihood(z, mask).log_prob(obs)
        )(particles)
        # log p(yₖ | y₁:ₖ₋₁) ≈ log (1/P_n) ∑ᵢ wₖ⁽ⁱ⁾
        log_sum = einx.logsumexp("[particle]", log_weights)  # (P_n,) → ()
        log_increment = log_sum - jnp.log(NUM_PARTICLES)  # → ()
        # resample: i ~ Categorical(wₖ / ∑ w)
        ancestors = jax.random.categorical(           # → (P_n,)
            resample_key, log_weights, shape=(NUM_PARTICLES,)
        )
        particles = particles[ancestors]              # (P_n, N)
        return particles, (particles, log_increment)

    day_keys = jax.random.split(time_key, observations.shape[0])  # → (T, 2)
    _, (filtered, log_increments) = jax.lax.scan(     # → (T, P_n, N), (T,)
        day, particles, (observations, controls, masks, day_keys)
    )
    # log p(y₁:T | θ) = ∑ₖ log p(yₖ | y₁:ₖ₋₁)
    log_evidence = einx.sum("time ->", log_increments)  # (T,) → ()
    return filtered, log_evidence

Why the linear case closes and the nonlinear case does not

Linear-Gaussian Gaussians stay Gaussian under linear maps, sums and conditioning, so every integral above is matrix algebra: the predict step is \(\mathbf M\boldsymbol\mu\), \(\mathbf M\mathbf P\mathbf M^\top + \mathbf Q\); the update is the Kalman gain. Three consequences:
  • the posterior is one Gaussian;
  • its mean is linear in \(y\);
  • its covariance does not depend on \(y\) at all.
Nonlinear The predict integral pushes a density through \(f_\theta\) and the update multiplies by a likelihood through \(h\); neither keeps a Gaussian Gaussian. The posterior can skew or split into several modes, its mean is a nonlinear function of \(y\), and its spread depends on what was observed. No finite set of numbers describes it in general.

The scalar example shows all three effects. With a speed-squared observation, the posterior has a branch for each sign of the current, weighted by the prior, and its shape changes with \(y\):

Two patterns to keep. The linearised standard deviation is 0.24 for every \(y\): that is the linear-Gaussian property that the posterior covariance ignores the data, carried into a problem where it is false (the exact sd runs from 0.25 to 1.19). And the Laplace approximation becomes more confident as the evidence for two branches grows: a single Gaussian cannot say "east or west". (For a truly linear observation, \(y = z + \varepsilon\), the grid and the closed-form Kalman update agree to four decimals.)

Step 3 · The emulator is a learned conditional density

The expensive object in step 2 is the transition: it is evaluated or sampled for every particle, ensemble member or iteration. An emulator replaces that one density with a learned one, keeping the same interface:

\[ q_\phi(z_k\mid z_{k-1},\theta, x, u_k)\;\approx\;p(z_k\mid z_{k-1},\theta, x, u_k). \]

Train it on transitions drawn by running step 1, by maximum likelihood. That is the same as minimising the KL divergence from the simulator's transition to the emulator's, averaged over the states and parameters the simulations visit:

\[ \phi^\star = \arg\min_\phi\ \mathbb E_{p(z_{k-1},\theta)}\Big[\mathrm{KL}\big(p(z_k\mid z_{k-1},\theta)\ \|\ q_\phi(z_k\mid z_{k-1},\theta)\big)\Big] = \arg\min_\phi\ \mathbb E_{p(z_{k-1},\theta,z_k)}\big[-\log q_\phi(z_k\mid z_{k-1},\theta)\big]. \] 
# Shapes: S simulated transitions (sim); N state values (state); P parameters (param)


class EmulatedTransition(eqx.Module):
    """q_φ(zₖ | zₖ₋₁, θ, x, uₖ): a learned conditional density, same interface as p."""

    network: eqx.Module

    def __call__(self, state, params, covariates, control) -> Dist:
        # user
        # (μ_φ, log σ_φ) = network(zₖ₋₁, θ, x, uₖ)
        mean, log_scale = self.network(state, params, covariates, control)  # → (N,) ×2
        # not pinned (distribution library)
        # q_φ(zₖ | ·) = 𝒩(μ_φ, diag σ_φ²); a flow or a diffusion model also fits here
        return Normal(mean, jnp.exp(log_scale))


def emulator_loss(emulator, previous, params, covariates, controls, nexts):
    # pairs (zₖ₋₁, θ, uₖ, zₖ) drawn by running step 1: zₖ ~ p(zₖ | zₖ₋₁, θ, x, uₖ)
    def nll(prev, theta, control, nxt):
        # −log q_φ(zₖ | zₖ₋₁, θ, x, uₖ)
        return -emulator(prev, theta, covariates, control).log_prob(nxt)

    losses = jax.vmap(nll)(previous, params, controls, nexts)  # → (S,)
    # 𝔼_p[−log q_φ] = 𝔼_{zₖ₋₁,θ}[ KL(p(zₖ|·) ‖ q_φ(zₖ|·)) ] + const
    return einx.mean("sim ->", losses)                # (S,) → ()

The deterministic emulator is the case \(q_\phi = \delta\big(z_k - \hat f_\phi(z_{k-1},\theta)\big)\). Its log-likelihood is undefined, so it is trained by mean squared error instead, which is the Gaussian log-likelihood with a fixed variance. What is lost is exactly the spread: a deterministic emulator claims to be right everywhere, and step 4 then trusts it fully. A learned \(\sigma_\phi\) reports where the emulator is unsure, and that uncertainty flows into the posterior like model error.

The expectation is over \(p(z_{k-1},\theta)\): the states and parameters the training simulations visit. An emulator is only trained where step 1 went. Step 4 will use it where the posterior puts mass, which may be a different place.

In the scalar example the "simulator" is the observation \(p(y\mid z) = \mathcal N(z^2, 0.25^2)\). An emulator \(q_\phi(y\mid z)\) trained only on the prior's typical range \(|z|\lesssim2\) is unconstrained beyond it; a posterior that reaches past it, such as the two branches near \(\pm2.2\) after observing \(y = 5\), rests on the emulator's extrapolation.

Step 4 · Emulator-based inference: the same posterior, one density swapped

Put \(q_\phi\) in place of the simulator's transition and run step 2 unchanged. The target becomes

\[ p_\phi(\theta, z\mid y) = \frac{p(\theta)\;q_\phi(z\mid\theta)\;p(y\mid z)}{p_\phi(y)}, \qquad q_\phi(z\mid\theta) = p(z_0\mid\theta)\prod_k q_\phi(z_k\mid z_{k-1},\theta). \]

In code this is one argument: pass the emulator as the model's transition to the same log_joint or particle_filter. Dividing the two posteriors shows exactly how emulator error enters:

\[ \frac{p_\phi(\theta, z\mid y)}{p(\theta, z\mid y)} = \frac{q_\phi(z\mid\theta)}{p(z\mid\theta)}\cdot\frac{p(y)}{p_\phi(y)} . \]

The posterior is distorted by the emulator's density ratio, renormalised. Errors where the posterior has no mass do not matter; errors where it does matter fully. So the emulator's training distribution (step 3's expectation) should cover the regions that posteriors visit, which is why emulators are often refined with simulations drawn near the posterior.

Step 5 · Amortized inference: learn the posterior as a function of the data

Steps 2 and 4 solve a new problem for every window of observations. Step 5 learns a conditional density that answers for all of them at once:

\[ q_\psi(\theta, z\mid y)\;\approx\;p(\theta, z\mid y)\quad\text{for every } y . \]

The forward KL, averaged over the data the model can produce, needs only samples of the joint from step 1. The intractable posterior drops out because it does not depend on \(\psi\):

\[ \mathbb E_{p(y)}\Big[\mathrm{KL}\big(p(\theta, z\mid y)\ \|\ q_\psi(\theta, z\mid y)\big)\Big] = \mathbb E_{p(\theta, z, y)}\big[-\log q_\psi(\theta, z\mid y)\big] + \text{const}. \]

That is simulation-based inference: simulate \((\theta, z, y)\) triples, fit a conditional density, done. The alternative is the reverse KL per window, the ELBO, which needs the likelihood but no simulated truth:

\[ \mathrm{ELBO}(\psi; y) = \mathbb E_{q_\psi(\theta, z\mid y)}\big[\log p(\theta)\,p(z\mid\theta)\,p(y\mid z) - \log q_\psi(\theta, z\mid y)\big] \le \log p(y). \]

Forward KL tends to spread mass over every mode (it is penalised for missing one); reverse KL tends to pick one (it is penalised for putting mass where the posterior has none). The amortization gap is what one network loses against solving each window separately.

# Shapes: S simulated windows (sim); P parameters (param); T, N, M as before;
#         L posterior draws (draw)


def amortized_loss(posterior_net, params, states, observations, masks):
    # (θ, z, y) ~ p(θ, z, y): S draws of sample_joint, nothing else is needed
    def nll(theta, z, y, m):
        # user
        # q_ψ(θ, z | y, m): a conditional flow, diffusion or mixture
        density = posterior_net(y, m)
        # −log q_ψ(θ, z | y)
        return -density.log_prob((theta, z))

    losses = jax.vmap(nll)(params, states, observations, masks)  # → (S,)
    # 𝔼_{p(y)}[ KL(p(θ, z | y) ‖ q_ψ(θ, z | y)) ] = 𝔼_{p(θ,z,y)}[−log q_ψ] + const
    return einx.mean("sim ->", losses)                # (S,) → ()


def calibration_rank(posterior_net, model, *, key, num_draws=99):
    """Simulation-based calibration: the rank of the true θ among posterior draws."""
    sim_key, draw_key = jax.random.split(key)
    # θ* ~ p(θ), y ~ p(y | θ*)
    true_params, _, observations = sample_joint(model, *INPUTS, key=sim_key)
    draw_keys = jax.random.split(draw_key, num_draws)  # → (L, 2)
    # θ⁽ˡ⁾ ~ q_ψ(θ | y)
    draws = jax.vmap(                                 # → (L, P)
        lambda k: posterior_net(observations, MASKS).sample_params(k)
    )(draw_keys)
    below = draws < true_params                       # (L, P), (P,) → (L, P)
    # rank = #{l : θ⁽ˡ⁾ < θ*}, uniform on 0…L when q_ψ is calibrated
    return einx.sum("draw param -> param", below)     # (L, P) → (P,)

# Shapes: L posterior draws (draw); N state values (state); J forecast days (lead);
#         M observations per day (obs)


def use_posterior(model, posterior_draws, covariates, controls, mask, *, key):
    """From posterior samples of (θ, z_K) to estimates, a forecast and a predictive."""
    params, final_states = posterior_draws            # (L, P), (L, N)

    # --- estimate: summaries of p(z_K | y) ---
    # 𝔼[z_K | y] ≈ (1/L) ∑ₗ z_K⁽ˡ⁾
    mean = einx.mean("draw state -> state", final_states)  # (L, N) → (N,)
    per_state = einx.rearrange("draw state -> state draw", final_states)  # → (N, L)
    # 5 % and 95 % quantiles of each state value
    bounds = jax.vmap(lambda v: jnp.quantile(v, LEVELS))(per_state)  # → (N, 2)

    # --- forecast: p(z_{K+j} | y) = ∫ p(z_{K+j} | z_K, θ) p(z_K, θ | y) dz_K dθ ---
    def rollout(theta, state, rollout_key):
        def day(state, inputs):
            control, day_key = inputs
            # z_{K+j} ~ p(z_{K+j} | z_{K+j−1}, θ): simulator, or emulator q_φ
            state = model.transition(state, theta, covariates, control).sample(day_key)
            return state, state

        day_keys = jax.random.split(rollout_key, controls.shape[0])  # → (J, 2)
        _, path = jax.lax.scan(day, state, (controls, day_keys))  # → (J, N)
        return path

    forecast_key, predictive_key = jax.random.split(key)
    rollout_keys = jax.random.split(forecast_key, final_states.shape[0])  # → (L, 2)
    # one forecast path per posterior draw: an ensemble with honest spread
    forecast = jax.vmap(rollout)(params, final_states, rollout_keys)  # → (L, J, N)

    # --- predict: p(ỹ | y) = ∫ p(ỹ | z) p(z | y) dz, for a new observation ---
    predictive_keys = jax.random.split(predictive_key, final_states.shape[0])
    # ỹ⁽ˡ⁾ ~ p(ỹ | z⁽ˡ⁾)
    predictive = jax.vmap(                            # (L, N) → (L, M)
        lambda z, k: model.likelihood(z, mask).sample(k)
    )(forecast[:, 0], predictive_keys)

    # --- event probability: P(A | y) = 𝔼[𝟙_A(z) | y] ---
    # user
    # 𝟙_A(z): e.g. "the jet sits north of 40° N", per draw
    in_event = event_indicator(forecast[:, -1])       # (L, N) → (L,)
    probability = einx.mean("draw ->", in_event)      # (L,) → ()
    return mean, bounds, forecast, predictive, probability

Three lessons that hold well beyond the toy. The posterior mean is a fine summary of a unimodal posterior and a misleading one here: it sits in the valley between the branches, at a current the water almost certainly does not have. And every use above needs draws, not a single field: a deterministic analysis can be estimated from, but it cannot be forecast with honest spread or turned into a probability.

The posterior predictive is the model's forecast of new data after seeing the old: \(p(\tilde y\mid y) = \int p(\tilde y\mid z)\,p(z\mid y)\,\mathrm dz\). If held-out observations fall in its tails more or less often than its stated probabilities, something is wrong. If the misfit is random, the inner loop (re-estimate \(z\) and \(\theta\)) is enough. \[ \frac{p(\mathcal M_1\mid y)}{p(\mathcal M_2\mid y)} = \frac{p(y\mid\mathcal M_1)}{p(y\mid\mathcal M_2)}\cdot\frac{p(\mathcal M_1)}{p(\mathcal M_2)}, \qquad p(y\mid\mathcal M) = \text{step 2's normaliser}. \]
