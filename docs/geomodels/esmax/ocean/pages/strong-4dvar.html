4D-Var: fitting a model trajectory to a window of observations

Four-dimensional variational assimilation (4D-Var) asks one question: which initial state, run forward through the model, best explains every observation in a time window, without straying far from what we believed before? This page is the background for the learned data assimilation page: the intuition, the mathematics, how the gradient is computed, three classic algorithms, and how it maps onto an ocean problem.

TL;DR

One cost, one gradient, three ways to minimise

  • 4D-Var is the MAP estimate of the initial state under a Gaussian background, Gaussian observation errors and a model with no error (strong constraint). The cost is minus the log posterior.
  • The control is the initial state \(\vect{x}_0 \in \mathbb{R}^{D_x}\); every later state \(\vect{x}_k = \vect{x}(t_k)\) is the model run from it. The observations at all times pull on \(\vect{x}_0\) through the model.
  • The gradient is one adjoint run: the backward sweep of the tangent-linear model. In JAX it is reverse-mode differentiation of the forward run; checkpointing trades memory for recomputation.
  • Classic minimises the full nonlinear cost with a quasi-Newton method. Incremental relinearises a few times and solves quadratic sub-problems with CG. Reduced-basis optimises a few coefficients of a basis instead of every grid value.
  • On Lorenz-96 all three reach the same analysis error (0.20, from a background error of 1.00), with very different costs.

Intuition

A 3D-Var or optimal-interpolation analysis corrects one snapshot with the observations at that time. 4D-Var corrects a trajectory: it chooses the starting point, lets the model run, and scores the whole run against everything observed in the window. Two consequences follow.

  • Observations spread information through the dynamics. An observation at day 7 constrains day 0 along exactly the directions the model carries from day 0 to day 7. Places never observed are still corrected, because the flow brings observed water to them or them to it.
  • The model is a hard constraint. The analysed trajectory is a true model solution: balanced, smooth in time, consistent with the physics. That is also its weakness: if the model is wrong, the analysis has nowhere to put the error (the weak-constraint form relaxes this).

A mechanical picture: each observation is a spring pulling the trajectory toward it, with stiffness \(1/\sigma_\varepsilon^2\); the background is a spring on the initial state with stiffness \(\gmat{\Sigma}_x^{-1}\); the model is a rigid rod connecting all times. 4D-Var finds where the rod comes to rest.

The running example is Lorenz-96: 40 values around a latitude circle, chaotic, a standard data-assimilation test bed (the one vardax and somax use). The window is 10 observation times of 10 model steps each; every second site is observed with error \(\sigma_\varepsilon = 1\); the background error is \(\sigma_x = 1\) with a correlation length of 2 sites.

Where it comes from

In the terms of the six-step page, 4D-Var is step 2 for one particular set of densities. The prior on the initial state, the transition, and the likelihood are

\[ p(\vect{x}_0) = \mathcal{N}(\gvect{\mu}_x, \gmat{\Sigma}_x), \] \[ p(\vect{x}_k \mid \vect{x}_{k-1}) = \delta(\vect{x}_k - f_k(\vect{x}_{k-1})), \] \[ p(\vect{y}_k \mid \vect{x}_k) = \mathcal{N}(h_k(\vect{x}_k), \gmat{\Sigma}_{\varepsilon,k}). \]

The point-mass transition makes every state a function of \(\vect{x}_0\), so the posterior is over \(\vect{x}_0\) alone, and its negative log is, up to a constant, the 4D-Var cost. 4D-Var returns that posterior's mode (the MAP estimate). It is the right summary when the posterior has one dominant, near-Gaussian peak, and the Laplace approximation around the mode then gives its spread. Replacing the point mass by \(\mathcal{N}(f_k(\vect{x}_{k-1}), \gmat{\Sigma}_\eta)\) gives weak-constraint 4D-Var, in which the model errors become extra controls.

The cost

\[ \mathcal{J}(\vect{x}_0) = \underbrace{\frac{1}{2} \Vert \vect{x}_0 - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}}}_{\text{background}} + \underbrace{\frac{1}{2} \sum_{k=1}^{T} \Vert \vect{y}_k - h_k(f_{k \leftarrow 0}(\vect{x}_0)) \Vert^2_{\gmat{\Sigma}_{\varepsilon,k}^{-1}}}_{\text{observations}}, \] \[ \Vert \vect{r} \Vert^2_{\mat{W}} = \vect{r}^\top \mat{W} \vect{r}. \]

With the change of variable \(\vect{x}_0 = \gvect{\mu}_x + \gmat{\Sigma}_x^{1/2}\gvect{\xi}\) the background term becomes \(\frac{1}{2}\Vert \gvect{\xi}\Vert^2\): all directions of \(\gvect{\xi}\) are equally likely a priori, the problem is far better conditioned, and \(\gmat{\Sigma}_x^{-1}\) is never needed. This "control-variable transform" is how operational 4D-Var is run.

The gradient: the adjoint recursion

Write \(\nabla_{\vect{x}_k}\mathcal{J}_{\text{o},k} = \mat{H}_k^\top \gmat{\Sigma}_{\varepsilon,k}^{-1}(h_k(\vect{x}_k) - \vect{y}_k)\) for the observation misfit at time \(k\), pulled back to the state. Starting from \(\vect{x}^\dagger_{T+1} = \vect{0}\), sweep backwards:

\[ \vect{x}^\dagger_k = \nabla_{\vect{x}_k}\mathcal{J}_{\text{o},k} + \mat{F}_{k+1}^\top \vect{x}^\dagger_{k+1}, \text{ for } k = T, \ldots, 1, \] \[ \nabla_{\vect{x}_0}\mathcal{J} = \gmat{\Sigma}_x^{-1}(\vect{x}_0 - \gvect{\mu}_x) + \mat{F}_1^\top \vect{x}^\dagger_1, \] \[ \nabla_{\gvect{\xi}}\mathcal{J} = \gvect{\xi} + (\gmat{\Sigma}_x^{1/2})^\top \mat{F}_1^\top \vect{x}^\dagger_1. \]

The adjoint carries each misfit backwards along the trajectory, through the transposed tangent-linear model, accumulating as it goes. Its cost is about one forward run, independent of the number of controls: that is why 4D-Var is feasible for millions of state values.

import jax
import jax.numpy as jnp
import lineax as lx
import optimistix as optx
import vardax

# Shapes: N = 40 state values (state); T = 10 observation times (time);
#         M = 20 observed values per time (obs)


def rollout(forward, initial, num_times):
    def interval(state, _):
        # user (forward.step: one observation interval, vardax's ForwardModel)
        # x_k = f_k(x_{k−1})
        state = forward.step(state, forward.dt)       # (N,) → (N,)
        return state, state

    # x_{1:T}: the model trajectory from x₀
    _, states = jax.lax.scan(interval, initial, None, length=num_times)  # → (T, N)
    return states


def cost(whitened, args):
    forward, background, prior_sqrt, observations, obs_index, obs_std = args
    # x₀ − μ_x = Σ_x^{1/2} ξ
    increment = prior_sqrt.mv(whitened)               # (N,) → (N,)
    # x₀ = μ_x + Σ_x^{1/2} ξ
    initial = background + increment                  # (N,)
    states = rollout(forward, initial, observations.shape[0])  # → (T, N)
    # h_k(x_k): the observed entries of each state
    predicted = states[:, obs_index]                  # (T, N) → (T, M)
    # y_k − h_k(x_k)
    misfit = observations - predicted                 # (T, M)
    # r_k = Σ_ε^{−1/2} (y_k − h_k(x_k)), diagonal Σ_ε = σ_ε² I
    residual = misfit / obs_std                       # (T, M)
    # ‖r_k‖² summed over the window
    misfit_sq = einx.sum("time obs ->", residual**2)  # (T, M) → ()
    # 𝒥_o = ½ ∑_k ‖y_k − h_k(x_k)‖²_{Σ_ε⁻¹}
    obs_cost = 0.5 * misfit_sq                        # → ()
    # 𝒥_b = ½ ‖x₀ − μ_x‖²_{Σ_x⁻¹} = ½ ‖ξ‖²
    background_cost = 0.5 * einx.dot("state, state ->", whitened, whitened)  # → ()
    # 𝒥(ξ) = 𝒥_b + 𝒥_o
    return background_cost + obs_cost

Curvature, convergence, and spread

The Gauss–Newton Hessian, in whitened variables, and the matching Laplace covariance of the analysis are

\[ \gmat{\Lambda}_{\xi \mid y} = \mat{I} + \sum_k (\mat{H}_k \mat{F}_{k \leftarrow 0} \gmat{\Sigma}_x^{1/2})^\top \gmat{\Sigma}_{\varepsilon,k}^{-1} (\mat{H}_k \mat{F}_{k \leftarrow 0} \gmat{\Sigma}_x^{1/2}), \] \[ \gmat{\Sigma}_{x_0 \mid y} \approx \gmat{\Sigma}_x^{1/2} \gmat{\Lambda}_{\xi \mid y}^{-1} (\gmat{\Sigma}_x^{1/2})^\top. \]

Its eigenvalues are 1 plus "how strongly the window's observations constrain each direction"; CG converges in about as many iterations as there are eigenvalues well above 1, which is why the whitened form converges fast. The same Hessian, through a few Lanczos vectors, gives the posterior spread. A last check needs no truth: at the minimum, \(2\mathcal{J}^\star / N_\text{obs} \approx 1\) for \(N_\text{obs}\) observations if \(\gmat{\Sigma}_x\) and \(\gmat{\Sigma}_\varepsilon\) are right. Here \(N_\text{obs} = 200\) and \(2\mathcal{J}^\star / N_\text{obs} = \) 1.01.

Computing the gradient

Every 4D-Var algorithm needs \(\nabla_{\vect{x}_0}\mathcal{J}\), or products with the tangent-linear model and its adjoint. There are several ways to get them, and they differ in exactness, memory and run time.

Two adjoints appear in a differentiable 4D-Var and should not be confused. The forward adjoint differentiates the model trajectory, to get \(\nabla_{\gvect{\xi}}\mathcal{J}\) for the optimiser. The minimiser adjoint differentiates the analysis \(\vect{x}_0^\star(\vect{y}, \gvect{\theta})\) with respect to its inputs, which is needed only when 4D-Var sits inside a larger trained system (learned priors, hyperparameter tuning). There, unrolling the optimiser is the expensive route; the implicit function theorem gives \(\partial \vect{x}_0^\star / \partial \gvect{\theta} = -(\nabla^2_{\vect{x}_0}\mathcal{J})^{-1} \nabla^2_{\vect{x}_0 \gvect{\theta}}\mathcal{J}\) at the solution, which is what optimistix.ImplicitAdjoint does.

per iteration one forward run + one adjoint run

On Lorenz-96: 61 iterations, 64 forward + adjoint runs; the cost falls from 559 to 101 and the initial-state error from 1.00 to 0.20. Strengths: simple, robust to nonlinearity within the window. Weakness: every iteration runs the full nonlinear model twice (forward and adjoint), and quasi-Newton methods need many iterations on badly conditioned problems.

Algorithm 2 · Incremental 4D-Var

per outer loop one nonlinear run per inner iteration one tangent-linear + one adjoint run

Idea. Gauss–Newton. Linearise the observed trajectory around the current guess, solve the resulting quadratic problem for an increment with conjugate gradients, update, relinearise. The inner problem never runs the nonlinear model, and in operational systems it is often solved at lower resolution with simplified physics.

\[ \mathcal{J}^{(n)}(\delta\gvect{\xi}) = \frac{1}{2} \Vert \gvect{\xi}^{(n)} + \delta\gvect{\xi} \Vert^2 + \frac{1}{2} \Vert \vect{d}^{(n)} - \mat{H}_\text{win}^{(n)} \delta\gvect{\xi} \Vert^2, \] \[ \vect{d}^{(n)} = \gmat{\Sigma}_\varepsilon^{-1/2} \vect{y} - h_\text{win}(\gvect{\xi}^{(n)}), \] \[ (\mat{I} + \mat{H}_\text{win}^{(n)\top} \mat{H}_\text{win}^{(n)}) \delta\gvect{\xi} = \mat{H}_\text{win}^{(n)\top} \vect{d}^{(n)} - \gvect{\xi}^{(n)}, \] \[ \gvect{\xi}^{(n+1)} = \gvect{\xi}^{(n)} + \delta\gvect{\xi}. \]

Here \(h_\text{win}(\gvect{\xi}) = \gmat{\Sigma}_\varepsilon^{-1/2} h(f(\gvect{\mu}_x + \gmat{\Sigma}_x^{1/2}\gvect{\xi})) \in \mathbb{R}^{T D_y}\) stacks the whitened, observed trajectory, and \(\mat{H}_\text{win}^{(n)} = \mat{J}_{h_\text{win}}(\gvect{\xi}^{(n)}) \in \mathbb{R}^{T D_y \times D_x}\) is its Jacobian at \(\gvect{\xi}^{(n)}\), applied with jax.jvp and transposed with jax.vjp.

def observe(whitened):
    # h_win(ξ) = Σ_ε^{−1/2} h(f(μ_x + Σ_x^{1/2} ξ)), flattened over the window
    initial = background + prior_sqrt.mv(whitened)    # (N,)
    states = rollout(forward, initial, num_times)     # → (T, N)
    observed = states[:, obs_index] / obs_std         # (T, N) → (T, M)
    return einx.rearrange("time obs -> (time obs)", observed)  # → (T·M,)


whitened = jnp.zeros(N)                               # (N,), the background
for _ in range(NUM_OUTER):
    # --- outer loop: one nonlinear run, linearised around it ---
    # h_win(ξ) and its tangent linear v ↦ H_win v
    predicted, tangent = jax.linearize(observe, whitened)  # → (T·M,)
    # adjoint w ↦ H_winᵀ w
    adjoint = jax.linear_transpose(tangent, whitened)
    # d = Σ_ε^{−1/2} y − h_win(ξ): whitened innovations
    innovation = observations_white - predicted       # (T·M,)

    def gauss_newton(v):
        # (I + H_winᵀ H_win) v: one tangent-linear and one adjoint run
        (projected,) = adjoint(tangent(v))            # (N,) → (N,)
        return v + projected

    hessian = lx.FunctionLinearOperator(
        gauss_newton, jax.ShapeDtypeStruct((N,), whitened.dtype),
        lx.positive_semidefinite_tag,
    )
    # b = H_winᵀ d − ξ  (= −∇_{δξ} 𝒥 at δξ = 0)
    (pulled,) = adjoint(innovation)                   # (T·M,) → (N,)
    rhs = pulled - whitened                           # (N,)
    # --- inner loop: CG on the quadratic, no nonlinear runs ---
    # not pinned (lineax)
    # δξ = (I + H_winᵀ H_win)⁻¹ b
    step = lx.linear_solve(                           # → (N,)
        hessian, rhs, solver=lx.CG(rtol=1e-8, atol=1e-8, max_steps=NUM_INNER)
    ).value
    # ξ ← ξ + δξ, then relinearise
    whitened = whitened + step                        # (N,)

# today (vardax)
# vardax's version solves in x-space with Σ_x⁻¹ applied by CG (no Σ_x^{1/2} transform)
incremental = vardax.IncrementalFourDVar(
    forward, vardax.MaskedIdentity(), background, prior_cov, obs_cov,
    config=vardax.IncrementalConfig(n_outer=4, n_inner=25),
)

The first linearisation, around the background, captures only part of the nonlinear response over the window (\(\mathcal{J}\) = 204, against the minimum of 101). Three relinearisations reach the classic minimum. Strengths: few expensive nonlinear runs; inner problems are quadratic, so CG with the whitened Hessian converges quickly and predictably. Weakness: each outer loop trusts a linearisation; for long or very nonlinear windows the quadratic model can point the wrong way, and more outer loops (or a shorter window) are needed.

Algorithm 3 · Reduced-basis 4D-Var

per iteration one forward run + one adjoint run, over \(N_\Phi\) controls

Idea. Restrict the initial-state correction to the span of \(N_\Phi \ll D_x\) basis functions: \(\vect{x}_0 = \gvect{\mu}_x + \gmat{\Phi}\vect{z}_\Phi\), with a prior \(\vect{z}_\Phi \sim \mathcal{N}(\vect{0}, \gmat{\Sigma}_{z_\Phi})\). The optimiser then works in \(N_\Phi\) dimensions. The basis encodes what corrections are plausible: leading EOFs of past states or of an ensemble, Fourier or wavelet modes, radial basis functions on a coarse grid.

\[ \mathcal{J}(\vect{z}_\Phi) = \frac{1}{2} \vect{z}_\Phi^\top \gmat{\Sigma}_{z_\Phi}^{-1} \vect{z}_\Phi + \frac{1}{2} \sum_{k=1}^{T} \Vert \vect{y}_k - h_k(f_{k \leftarrow 0}(\gvect{\mu}_x + \gmat{\Phi}\vect{z}_\Phi)) \Vert^2_{\gmat{\Sigma}_{\varepsilon,k}^{-1}}, \] \[ \nabla_{\vect{z}_\Phi}\mathcal{J} = \gmat{\Sigma}_{z_\Phi}^{-1} \vect{z}_\Phi + \gmat{\Phi}^\top \mat{F}_1^\top \vect{x}^\dagger_1. \]

If \(\gmat{\Phi}\) holds the leading eigenvectors of \(\gmat{\Sigma}_x\) scaled by the square roots of their eigenvalues, this is exactly the whitened full problem truncated to \(N_\Phi\) directions. Anything outside the span is left at the background.

def cost_reduced(coeffs, args):
    forward, background, observations, obs_index, obs_std = args
    # δx₀ = Φ z_Φ
    increment = basis.operg(0.0, coeffs)              # (P,) → (N,)
    # x₀ = μ_x + Φ z_Φ
    initial = background + increment                  # (N,)
    states = rollout(forward, initial, observations.shape[0])  # → (T, N)
    # r_k = Σ_ε^{−1/2} (y_k − h_k(x_k))
    residual = (observations - states[:, obs_index]) / obs_std  # (T, M)
    # 𝒥_o = ½ ∑_k ‖r_k‖²
    obs_cost = 0.5 * einx.sum("time obs ->", residual**2)  # → ()
    # Σ_{z_Φ}⁻¹ z_Φ, diagonal
    scaled = basis.prior_inv(coeffs)                  # (P,)
    # 𝒥_b = ½ z_Φᵀ Σ_{z_Φ}⁻¹ z_Φ
    prior_cost = 0.5 * einx.dot("basis, basis ->", coeffs, scaled)  # → ()
    return prior_cost + obs_cost

Notes on vardax, from reading the code

Checked against vardax main (3e0f34a) on 24 Oct 2026. Several docs and the code disagree; each point is filed as a vardax issue.

  • Incremental4DVar is not incremental. It minimises the full nonlinear cost over basis coefficients with BFGS (the MASSH formulation). The Gauss–Newton method is IncrementalFourDVar. A rename (for example ReducedBasis4DVar) would remove the trap (#96).
  • No control-variable transform yet. IncrementalFourDVar applies \(\gmat{\Sigma}_x^{-1}\) with an inner CG solve at every Hessian product. The whitened form on this page is the proposed fix; the IncrementalConfig(cvt=True) shown in the docs does not exist (#97).
  • The docs' incremental right-hand side is incomplete. The code uses \(-\nabla_{\vect{x}_0}\mathcal{J}\) of the full nonlinear cost at the current outer iterate, which is the correct Gauss–Newton right-hand side. The docs give \(\sum_k (\mat{H}_k \mat{F}_{k \leftarrow 0})^\top \gmat{\Sigma}_\varepsilon^{-1} \vect{d}_k\), which drops the background term \(-\gmat{\Sigma}_x^{-1}(\vect{x}_0 - \gvect{\mu}_x)\); the two agree only on the first outer loop, where \(\vect{x}_0 = \gvect{\mu}_x\). The code is right and the docs need the fix (#98).
  • The posterior adapters omit the model. LaplaceCovariance and GaussNewtonHessian build \(\gmat{\Sigma}_x^{-1} + \mat{H}^\top \gmat{\Sigma}_\varepsilon^{-1} \mat{H}\) without \(\mat{F}_k\): a 3D-Var Hessian, not the 4D-Var one their docstrings state (#94).
  • forward_adjoint is stored but not used. StrongFourDVar rolls out with jax.lax.scan, so the gradient is plain reverse mode whatever adjoint is passed (#95).
  • Missing names in the docs: IncrementalFourDVar.posterior, vardax.utils.multi_start, and a no-argument LaplaceCovariance() (#99).
