Hybrid model taxonomy: what can be learned in an ocean model

The physical model is not one object. It is a stack of pieces: parameters, discretisation, terms, a tendency, an integrator, a step map, a rollout. Every hybrid or emulator learns one of those pieces and glues it back in one of a few ways. This page lists the ten that matter, on the same Gulf Stream QG example as the state-estimation page.

TL;DR

One signature, ten insides

  • Every type T1–T8 is the same operator: today's state, covariates, forcing and parameters in, tomorrow's state out. Any of them drops into the cycles, the DA and the rollouts of the last page unchanged. T9 and T10 change the signature.
  • Types differ in which layer is learned (the diagram below) and in how the learned piece is glued back: added, used as a coefficient, built into a conserving form, or substituted.
  • The training target splits them into two jobs. emulation reproduces the physical model faster (box 3, ground truth step 1). correction makes the model closer to the real ocean (box 6, ground truth a richer model or data).
  • The lower the learned layer, the more physics survives: conservation, freedom in Δt, a trustworthy adjoint. The higher, the more speed and the less structure.

The physical model, taken apart

The 1.5-layer QG model of the last page, written layer by layer. Let \(\nabla := \nabla_{\vect{s}}\) act on the horizontal coordinates \(\vect{s} = (s_1, s_2)\), \(\mathcal{A} = \nabla^2 - L_d^{-2}\) be the Helmholtz operator and \(J(a, b) = \partial_{s_1} a \partial_{s_2} b - \partial_{s_2} a \partial_{s_1} b\) the Jacobian.

\[ \begin{aligned} \text{diagnostic solve: } & \psi = \mathcal{A}^{-1}[q - \beta s_2]\\ \text{terms: } & \mathcal{F}[q] = \underbrace{-J(\psi, q)}_{\text{advection}} \underbrace{- \nu \nabla^6 \psi}_{\text{dissipation}} + \underbrace{u^\text{wind}}_{\text{wind forcing}}\\ \text{integrator: } & q \leftarrow \mathrm{RK4}_{\Delta t}[\mathcal{F}](q) = q + \frac{\Delta t}{6} \left(\mathcal{F}^{(1)} + 2 \mathcal{F}^{(2)} + 2 \mathcal{F}^{(3)} + \mathcal{F}^{(4)}\right)\\ \text{step map: } & \vect{x}_{k+1} = f(\vect{x}_k, \vect{u}_k; \gvect{\theta}) = \mathrm{RK4}_{\Delta t}[\mathcal{F}]^{48}(\vect{x}_k)\\ \text{rollout: } & \vect{x}_{1:T} = f_{1:T \leftarrow 0}(\vect{x}_0, \vect{u}_{1:T}; \gvect{\theta}) \end{aligned} \]

Below the terms sits the discretisation: \(J\) is the Arakawa stencil and \(\nabla^2\) the five-point stencil on the C-grid, and \(\mathcal{A}^{-1}\) is a spectral or sine-transform solve. Each layer is a function with a signature, and each can be swapped.

The sketch below is the model in code. Every type in this page is an edit to one or two of its lines.

import equinox as eqx
import finitevolx as fvx
import jax
from jaxtyping import Array, Float

# Shapes: T = 10 days (time); H, W = 130 × 130 grid with ghost ring
#         (height, width); V covariates, β s_2 first (variable);
#         48 RK4 substeps per day


class QGParams(eqx.Module):
    """Physical parameters θ = (L_d, ν) of the 1.5-layer QG model."""

    deformation_radius: Float[Array, ""]
    viscosity: Float[Array, ""]


def qg_tendency(
    pv: Float[Array, "height width"],
    covariates: Float[Array, "variable height width"],
    forcing: Float[Array, "height width"],
    params: QGParams,
    grid: fvx.CartesianGrid2D,
) -> Float[Array, "height width"]:
    # today (finitevolx)
    difference = fvx.Difference2D(grid)
    # today (finitevolx)
    jacobian = fvx.ArakawaJacobian2D(grid)
    beta_y = covariates[0]                            # (H, W)

    # --- diagnostic solve ---
    # q − β s_2
    relative_pv = pv - beta_y                         # (H, W) → (H, W)
    # L_d²
    radius_squared = params.deformation_radius**2     # → ()
    # L_d⁻²
    helmholtz_shift = 1.0 / radius_squared            # → ()
    # today* (finitevolx)
    # ψ = 𝒜⁻¹[q − β s_2],  𝒜 = ∇² − L_d⁻²
    streamfunction = fvx.pv_inversion(                # (H, W) → (H, W)
        relative_pv, grid.dx, grid.dy, lambda_=helmholtz_shift, bc="dst"
    )

    # --- terms ---
    # today (finitevolx)
    # J(ψ, q)
    jacobian_term = jacobian(streamfunction, pv)      # (H, W)
    # advection = −J(ψ, q)
    advection = -jacobian_term                        # (H, W)
    # today (finitevolx)
    # ∇²ψ
    laplacian_1 = difference.laplacian(streamfunction)  # (H, W)
    # today (finitevolx)
    # ∇⁴ψ = ∇²(∇²ψ)
    laplacian_2 = difference.laplacian(laplacian_1)   # (H, W)
    # today (finitevolx)
    # ∇⁶ψ = ∇²(∇⁴ψ)
    laplacian_3 = difference.laplacian(laplacian_2)   # (H, W)
    # dissipation = −ν ∇⁶ψ
    dissipation = -params.viscosity * laplacian_3     # (H, W)

    # ℱ[q] = −J(ψ, q) − ν∇⁶ψ + u^wind
    tendency = advection + dissipation + forcing      # (H, W)
    return tendency


def qg_day(
    pv: Float[Array, "height width"],
    covariates: Float[Array, "variable height width"],
    forcing: Float[Array, "height width"],
    params: QGParams,
    grid: fvx.CartesianGrid2D,
    *,
    dt: float = 1800.0,
    n_substeps: int = 48,
) -> Float[Array, "height width"]:
    def rhs(state):
        # user
        # ℱ[q; u_k, θ]
        return qg_tendency(state, covariates, forcing, params, grid)

    def substep(state, _):
        # today (finitevolx)
        # q ← RK4_Δt[ℱ](q), classic RK4
        state = fvx.rk4_step(state, rhs, dt)          # (H, W) → (H, W)
        return state, None

    # f(x_k, u_k; θ) = RK4_Δt[ℱ]⁴⁸(x_k)
    next_pv, _ = jax.lax.scan(                        # (H, W) → (H, W)
        substep, pv, None, length=n_substeps
    )
    return next_pv


def qg_rollout(
    initial_pv: Float[Array, "height width"],
    covariates: Float[Array, "variable height width"],
    forcing: Float[Array, "time height width"],
    params: QGParams,
    grid: fvx.CartesianGrid2D,
) -> Float[Array, "time height width"]:
    def day(state, daily_forcing):
        # user
        # x_k = f(x_{k−1}, u_k; θ)
        state = qg_day(                               # (H, W) → (H, W)
            state, covariates, daily_forcing, params, grid
        )
        return state, state

    # f_{1:T←0}(x₀, u_{1:T}; θ) = (x₁, …, x_T)
    _, trajectory = jax.lax.scan(                     # (H, W) → (T, H, W)
        day, initial_pv, forcing
    )
    return trajectory

Three axes

Which layer is learned

The diagram above. Lower layers (T1, T2) keep the most physics and fix the least; upper layers (T8, T9) keep the least and are fastest.

What it is trained against

Two jobs, three sources of reference, four loss levels. Let \(\vect{x}^\text{ref}\) be the reference trajectory and \(\mathcal{F}_\text{ref}\) its tendency.

JobReferenceGround truth box
emulation\(\vect{x}^\text{ref}\) from the physical model itselfstep 1
correction\(\vect{x}^\text{ref} = \mathcal{C}[\vect{x}^\text{hr}]\), a finer or richer run coarse-grained to our grida better step 1
correctionobservations \(\vect{y}_{1:T}\) through \(\mat{H}_k\)the ocean

The loss can sit at four levels, from cheapest to most faithful to how the model will be used:

\[ \begin{aligned} \mathcal{L}_\text{tendency}(\gvect{\theta}_\text{emu}) &= \mathbb{E} \Vert \mathcal{F}_\text{ref}[q] - \mathcal{F}[q; \gvect{\theta}_\text{emu}] \Vert^2\\ \mathcal{L}_\text{step}(\gvect{\theta}_\text{emu}) &= \mathbb{E} \Vert \vect{x}^\text{ref}_{k+1} - f(\vect{x}^\text{ref}_k; \gvect{\theta}_\text{emu}) \Vert^2\\ \mathcal{L}_\text{rollout}(\gvect{\theta}_\text{emu}) &= \mathbb{E} \sum_{k=1}^{T} \Vert \vect{x}^\text{ref}_k - f_{k \leftarrow 0}(\vect{x}^\text{ref}_0; \gvect{\theta}_\text{emu}) \Vert^2\\ \mathcal{L}_\text{obs}(\gvect{\theta}_\text{emu}) &= \mathbb{E} \sum_{k=1}^{T} \Vert \vect{y}_k - \mat{H}_k f_{k \leftarrow 0}(\vect{x}_0; \gvect{\theta}_\text{emu}) \Vert^2_{\gmat{\Sigma}_{\varepsilon,k}^{-1}} \end{aligned} \]

For correction against a finer run, the tendency target is the subgrid forcing: what the coarse physics misses when applied to the coarse-grained state,

\[ \mathcal{F}_\text{sub} = \mathcal{C}\left[\mathcal{F}_\text{hr}[q^\text{hr}]\right] - \mathcal{F}_\text{phys}\left[\mathcal{C}[q^\text{hr}]\right]. \]

The tendency and one-step losses are a priori: cheap, but the model never sees its own errors, so long rollouts often go unstable. The rollout and observation losses are a posteriori: they differentiate through the solver, which is what a JAX model makes affordable. The observation loss also needs each window's \(\vect{x}_0\), so learning from data is 4D-Var with \(\gvect{\theta}_\text{emu}\) added to the control vector.

T2

Learned discretisation

layer: discretisation

The PDE is fixed; the stencil weights are learned. With offsets \((p, r) \in \mathcal{O}\) and weights \(w\), a derivative or face value is a weighted sum of shifted copies. In flux form the update telescopes, so the domain integral of \(q\) is conserved whatever the weights are:

\[ (\mathcal{D}[q])_{j,i} = \sum_{(p, r) \in \mathcal{O}} w_{pr}(q; \gvect{\theta}_\text{emu}) q_{j+p, i+r} \] \[ \mathcal{F}[q] = -\nabla \cdot \left(\vect{v} q^\text{face}(q; \gvect{\theta}_\text{emu})\right) . \]

T10

Learned representation

layer: representation (orthogonal)

What the structure implies

Emulation and correction are different boxes

An emulator answers "same model, faster" and is scored against step 1. A correction answers "better model" and is scored against a richer model or the ocean. Benchmarking a closure against the QG model, or an emulator against observations, measures the wrong thing. For this QG example emulation buys little; correction is where the value is.

Additive terms are not identifiable

Fit θ and an additive \(\mathcal{G}\) together and the network can learn part of \(\nu \nabla^6 \psi\) or of \(\beta s_2\), leaving θ meaningless. The fixes, in order of preference: a parametric or structural form (T4, flux-form T3); fit θ first and freeze it; penalise \(\Vert \mathcal{G} \Vert^2\).

For 4D-Var, learn low in the stack

T1–T5 keep a classical integrator, so stability, Δt and the meaning of the adjoint come from the physics. T6–T9 trade that for speed, and a step map that matches values can still have the wrong Jacobian. If a type above T5 is meant for step 4, its training should include Jacobian–vector products, not only values.

A priori training is a trap for T3–T5

A term that fits the subgrid forcing perfectly on reference states meets its own errors in a rollout and can blow up within days. Use the a priori loss to initialise, then train a posteriori through the solver.
