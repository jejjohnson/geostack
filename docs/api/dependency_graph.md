+++ {"part": "abstract"}

geostack builds on eighteen repositories in four layers. This page draws how
they depend on one another, from what each one declares (base dependencies,
extras, dependency groups) and what its code actually imports (including
lazy, `try`-guarded and type-checking-only imports). It then states eight
rules that keep the graph free of cycles. The graph obeys them almost
everywhere: no edge points up a layer and no GeoModels repository imports
another. It has **one cycle, pipekit ⇄ geotoolz**, made by a single lazy
import in pipekit-train that is also broken. It also has **three imports
that their package does not declare**. [](#tbl-dg-violations) lists each one
with its fix.

What it shows:

- **Every edge between layers points down.** GeoModels uses GeoML, Numerics
  and GeoStack. GeoML uses Numerics and GeoStack. Numerics uses nothing above
  it.
- **gaussx is the foundation.** Every repository in Numerics, GeoML and
  GeoModels except geonnax reaches it. A breaking change in gaussx is a
  change to almost the whole stack.
- **The GeoModels repositories are independent.** plumax, somax and radtrax
  import no one in their own layer.
- **The one cycle is inside GeoStack** (in red): pipekit-train imports
  `geopatcher.time` from geotoolz-patcher, and geotoolz depends on pipekit.
  The import is lazy and behind a `try`, so nothing fails at install time,
  but the two repositories can no longer be released, tested or reasoned
  about separately.

## The rules

Each rule is a check in `scripts/dependency_graph.py`. The name in brackets
is the rule's name in [](#tbl-dg-violations).

1. **Layers point down** (`upward`). A repository may depend on its own layer
   or a lower one: GeoStack and Numerics at the bottom, GeoML above them,
   GeoModels on top. GeoStack and Numerics never import each other.
2. **Within a layer, tiers point down** (`tier`). Each repository has a tier
   in its layer ([](#tbl-dg-tiers)) and imports only repositories of a lower
   tier. Two repositories of the same tier never import each other. The
   GeoModels repositories share one tier: code two of them need moves down
   to the layer below.
3. **Every edge counts.** Base dependencies, extras, dependency groups, and
   imports, whether at module level, inside a function, behind a `try` or
   under `TYPE_CHECKING`, all go into the graph. An optional edge is still an
   edge, and optional edges are where cycles hide: the one cycle today is a
   lazy, guarded import.
4. **No cycles** (`cycle`, `package-cycle`): not between repositories, and not
   between the packages of one workspace (pipekit's, geotoolz's, xrtoolz's,
   pyrox's).
5. **Every import is declared** (`undeclared`). A module-level import is a
   base dependency. A lazy or guarded one is an extra (or a base
   dependency). A `TYPE_CHECKING`-only import needs no declaration but still
   obeys rules 1 and 2. A dependency group (`dev`, `docs`, `da`) is for
   running tests and docs, not for code the package ships.
6. **A reverse edge is fixed by moving code, never by a shim.** When a lower
   repository needs something from a higher one, either the primitive moves
   down into the lower one, or the adapter moves up into the higher one (as
   an `integrations/` module behind an extra). A moved name leaves no
   re-export behind: its old path raises an `ImportError` naming its new
   home, because a re-export is a reverse edge
   ([Package boundaries](../geomodels/package_boundaries.md#pb-graph)).
7. **A third-party repository is a leaf** (`third-party`). georeader belongs
   to spaceml-org: we depend on it and never change it, and nothing of ours
   moves into it.
8. **A new repository arrives with its place** (`untiered`). Adding a
   submodule means adding it to `TIERS` in `scripts/dependency_graph.py` with
   its layer and tier, in the same pull request.

The tiers follow what each repository is for, not only the edges it has
today. filterax could sit at tier 0, since it imports only gaussx. It is
placed with vardax and pyrox among the inference libraries, so an inference
library cannot start importing another one without a decision
([open question 1](#dg-open)).

## Where the graph breaks the rules today

:::{table} Every rule the graph breaks, from the check. The check fails on a row not listed in `KNOWN` in the script, and on a listed one that is fixed, so this table only shrinks.
:label: tbl-dg-violations

<!-- violation-table:begin -->
| Rule | From | To | Where | Why, and the fix |
|---|---|---|---|---|
| cycle | geotoolz | pipekit | `geotoolz ⇄ pipekit` | pipekit-train's _xreader lazily imports geopatcher.time (which no longer exists); Report 16 D2 moves the dataset to geopatcher.integrations.train |
| tier | pipekit | geotoolz | `pipekit-train → geotoolz-patcher` | the same import |
| undeclared | gauss-flows | gaussx | `src/gauss_flows/_src/flows/transform_filter.py (lazy)` | a try-guarded import in transform_filter.py; declare a [gaussx] extra |
| undeclared | pipekit-train | geotoolz-patcher | `src/pipekit_train/xarray_window.py (guarded)` | the same import |
| undeclared | somax | filterax | `somax/_src/da/filterax_bridge.py (module)` | module-level imports in somax/_src/da, declared only in the da dependency group; make it an extra |
<!-- violation-table:end -->
:::

The fixes, in order of how much they matter:

1. **Move pipekit-train's window dataset into geotoolz-patcher**
   (`geopatcher.integrations.train`, behind `geotoolz-patcher[train]`). This
   is [Report 16](../reports/16_geo_data_stack.md#r16-ws-d)'s step D2, and
   rule 6's "move the adapter up". It removes the cycle, the tier break and
   the undeclared import, which are three rows for one import. The import is
   broken anyway: geotoolz-patcher has `geopatcher.temporal`, not
   `geopatcher.time`.
2. **Make somax's filterax import an extra.** `somax/_src/da` imports
   filterax at module level, but somax declares filterax only in its `da`
   dependency group, so `pip install somax` gives a package whose `da`
   module cannot import. A `[da]` extra with filterax and vardax fixes it.
3. **Declare gauss_flows's gaussx integration as an extra.** The `try`-guarded
   import is deliberate, but undeclared, so nothing pins which gaussx it
   works with. A `[gaussx]` extra keeps it optional and pinned.

(dg-open)=
## Open questions

1. **May the inference libraries import each other?** filterax, vardax and
   pyrox share tier 2. A hybrid ensemble–variational scheme in vardax would
   want filterax; that needs one of them moved up a tier, and the order
   decided once.
2. **Is tier 3 of GeoML needed?** xtremax is there only because its
   tutorials use pyrox. If the tutorials moved to geostack's notebooks,
   xtremax would drop to tier 1 and the tier would be empty.
3. **Should dependency groups count?** Rule 3 counts them, so a `docs` group
   cannot point up a layer or close a cycle. The cost is that a tutorial
   dependency constrains the library, as xtremax's does.
