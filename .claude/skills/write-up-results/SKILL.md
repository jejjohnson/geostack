# Write up the results

Read contract 6 and "Documentation" in `AGENTS.md` first. The site is
MyST Markdown built by `mystmd` from `myst.yml` at the repo root;
`pages.yml` deploys `_build/html` on every push to `main`.

## 1. Where it goes

<!-- template-example: the page names are the example's; keep the structure. -->

| Content | Page |
|---|---|
| Motivation, related work, problem statement | `docs/notes/background.md` |
| Approach, model, training procedure, evaluation protocol | `docs/notes/methods.md` |
| How to install and run the experiments | `docs/tutorials/getting_started.md` |
| Results, ablations, discussion | a new page, e.g. `docs/notes/results.md` |
| The package's API | `docs/api/capabilities.md` (generated by `make capabilities`) |

A new page is added to the `toc` in `myst.yml`, written like the existing
entries (`- file: docs/notes/results`; mystmd prints an "Extension
inferred" warning for entries without `.md`, which is harmless); a page
that is not in the toc is not built.

## 2. Numbers and figures come from the pipeline

- Every number quoted is read from a pipeline output
  (`pixi run dvc metrics show`, `results/metrics/*.json`,
  `results/tables/`) of a committed `dvc.lock`, not from a one-off
  session; say which experiment / config produced it.
- Figures are made by a notebook (`notebooks/02_results.py` or a new one —
  the `add-notebook` skill), saved under `docs/images/<notebook_name>/`
  and committed with it. Include one with:

  ```markdown
  :::{figure} ../images/02_results/loss_curve.png
  :label: fig-loss
  :alt: Training and validation loss per epoch

  Training and validation loss for the baseline (`configs/train.yaml`).
  :::

  As {numref}`fig-loss` shows, …
  ```

  (the path is relative to the page).
- Equations in `$…$` / `$$…$$`; give a key result a label to refer to it.

## 3. Citations

- Add the BibTeX entry to `references.bib` (with a DOI or URL), then cite
  it: `[@goodfellow2016deep]` (parenthetical), `@goodfellow2016deep`
  (narrative), or the roles `{cite:p}` / `{cite:t}`. The bibliography is
  listed in `myst.yml` (`project.bibliography`), so every page can cite.
- An unknown key does not fail the build: it is a `⚠️ … Could not link
  citation with label "<key>"` warning in the output, so read it.

## 4. Citation metadata (`CITATION.cff`)

Update `title`, `authors` (with ORCID), `version`, `date-released`,
`repository-code`, `url` and `abstract` when they change — at least for
each release (release-please bumps `pyproject.toml`, not this file).
`citation.yml` validates it on any change; locally:

```bash
uvx cffconvert --validate -i CITATION.cff
```

Keep the BibTeX block in `README.md` consistent with it.

## 5. Build and check

```bash
make docs                # myst build --html into _build/html (gitignored)
make docs-serve          # live preview
```

- Read the build output: `⛔️` lines are errors (unknown directives,
  unresolved toc entries), `⚠️` lines warnings (citation keys that do not
  link, inferred toc extensions). The build still finishes, so fix the
  ones on the pages you touched.
- If the book-theme download is blocked (`403 Forbidden`), clone
  `https://github.com/myst-templates/book-theme` somewhere outside the
  repo, point `site.template` in `myst.yml` at that directory **for the
  build only**, and restore `myst.yml` afterwards (`git diff myst.yml`
  must be empty).
- `pixi run -e docs docs-build` is what `pages.yml` runs.
