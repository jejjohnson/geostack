# The figure kinds

One section per kind: what goes where on the canvas, what to read from the library, and the argminax folder to copy from geostack's `docs/images/libraries/`. Every HTML figure is 1560 px wide and rendered at 2x; every SVG is 960 px wide.

## Overview

Four lanes left to right, joined by labelled `wire` connectors, and a row of slabs underneath.

1. **supply**: what the caller writes (the cost and its inputs, the solver, the model or the loop), one card each.
2. **the one idea**: the object the library is built around, with its equation in a mono box and one or two labelled terms (argminax: the minimum, the retrieval cost, the Hessian there).
3. **what it does**: one card per question or method, each naming its module in accent and its public names in code font.
4. **out**: what comes back, with the result the reader uses most drawn solid (`node solid`).

The slabs name each upstream library the package extends and what it takes from it. Read the README's core-idea table and its highlights; the figure says the same in pictures. Copy `argminax_overview/`.

## Role ladder

One row per rung the library has, highest first, from the `role-ladder` skill: a numbered circle, the role in bold and its grammar word muted ("4 algorithm · the sentence"), a caption on the right saying what that rung is in this library, and the public names as chips that wrap. A rung the library leaves to another library is dashed and holds that library's names; a third-party floor sits in a dashed side box with an arrow to the rung it plugs into; a "built on" row closes it. Place each name as the library's skill-shelf page does (`docs/design/skill_tree_<pkg>.md` here), and by the skill's §2 test where the page has no row yet. Copy `argminax_roles/`.

## Dependencies

The library at the top with its icon and tagline, the stack layers as boxes below, one card per package that imports it (what it is, and the library's modules it uses in small mono), dashed for an import through an extra with the extra named under it, grey arrows between dependents, a strip saying what the library builds on, and a legend. The edges are geostack's `docs/api/dependency_graph.md`; the modules are each package's `from <pkg>… import` lines on `main`. Copy `argminax_ecosystem/`.

## Code map

The library's public modules as cards inside one package box: each card has the module's name, what it does in a few words, and the libraries it imports as chips (dashed when through an extra). Arrows run only between the library's own modules and read "imports"; a module that imports nothing else from the package says so under its card. A strip names what every module imports. Read the `import` lines of each `_src/<module>/`, including the lazy ones inside functions (an extra is usually imported there). Copy `argminax_imports/`.

The exception hierarchy is a code map too: the standard-library parents dashed along the top, the package's base error in the middle, and each concrete error below with an arrow to each parent, what raises it in plain words, and where (the modules that raise it, or the extras it names). A strip says what is reported without an exception, such as a solve's `result`. Read the classes in the exceptions module and their `raise` sites; the figure follows the code where a docstring has fallen behind. Copy `argminax_exceptions/`.

## Hub

The central object in the middle lane, as one large equation with a short note on its shape and how it is held. A lane on the left for what builds it or uses it to get there, a lane on the right for what is read off it, three or four cards each. Every connector is labelled with the operation that links the card to the object (a solve, a factor, a log-determinant, a fixed point). Each card has a title in plain words, its module and public names, and its formula. Two slabs say what does the operations and what the large-scale variant is. Copy `argminax_hessian/`.

## Comparison

Two to four columns of the same height, one per way of doing the job, each drawn with the same picture so the difference is the only thing that changes (argminax: the chain of iterates, with the differentiated ones filled and the rest hollow). Under the picture, one equation and three rows of facts with the same keys in every column (argminax: adjoint, costs, right when). A key explains the marks; a slab says what all the columns share. Take the facts from the docstrings of the classes being compared. Copy `argminax_adjoints/`.

## Gallery

One column per structure or family, each with a pictogram of its shape (a small matrix drawn as cells, generated by a script before `ready()`), its defining equation, and the same rows of facts in each (storage, cost of a step, what it accepts). A full-width lane below for the special cases, and slabs for what reads every family out and what does its algebra. Take the facts from the table the gallery sits above, and keep its caveats (a cost that holds only for a built-in option). Copy `argminax_blr_families/`.

## Module detail

The overview's four lanes for one module: how the caller drives it, its variants, its state, and what it returns, with slabs for the libraries it rests on. Copy `argminax_blr/`.
